# 도입 순서

한 번에 전면 적용하지 않는다. 각 단계는 앞 단계의 측정 결과가 있을 때만 의미가 있다.
어느 단계도 특정 도구 설치를 전제하지 않는다 — 도구가 없으면 Git·소스·스키마·테스트로 같은 일을 한다.

1. **기준선 측정** — 탐색 실패율, 위치 파악에 걸리는 시간, 검증 대기 시간을 지금 값으로 기록한다.
2. **모듈 지도** — 도메인·모듈 경계와 공개 인터페이스, 경계를 넘는 계약과 담당자를 적는다.
3. **경계 감사** — 순환 의존, 숨은 공유 상태, 모두가 의존하는 모듈을 목록으로 남긴다. 이 단계에서 리팩터링하지 않는다.
4. **파일럿** — 경계가 비교적 뚜렷한 모듈 하나에서 파이프라인을 끝까지 돌린다.
5. **탐색 개선** — 파일럿에서 실제로 막힌 지점에 한해 탐색 수단을 보강하고 1번 지표를 다시 잰다.
6. **검증 개선** — 계약 테스트, 위험도 기준 특성화 테스트, 변경 범위 기반 테스트 선택을 붙인다.
7. **확대와 재측정** — 다음 모듈로 넓히고 1번 지표를 다시 잰다. 개선이 없으면 되돌린다.
8. **문서 최신성 담당** — L0/L1/L2 문서마다 갱신 담당과 재확인 주기를 정한다. 담당 없는 문서는 반드시 낡는다.
